## Kimi K3 的架构

K3 是 2.8T 参数的 MoE 模型，每 token 激活 104B；93 层里 69 层是 KDA 线性
注意力，24 层是全局 MLA；原生 1M 上下文，权重以 MXFP4 格式发布。整体结构
如下，点击图中部件可以看对应的说明：

<ArchViz client:visible />

### 1M 上下文的 KV cache

先算显存。按 MLA 压缩后 27 KB/token(24 层合计)线性外推，93 层全部用
MLA 时，1M token 的一个请求要占约 110 GB；未压缩的 MHA 还要再大一个
数量级。这个数字决定了大部分层不能保留 softmax attention。

K3 按 3 KDA + 1 MLA 交错。KDA 层的状态固定大小(整机约 0.4 GB/请求)，
每步原地覆写，不随上下文增长；MLA 层保留全局 attention，且全模型不加
RoPE(NoPE)，位置信息由 KDA 的递归隐式提供：

<CacheViz client:visible />

24 层 MLA 在 1M token 时约 28 GB，是全 MLA 假想值的 1/3.9。计算量同理：
softmax attention 每生成一个 token 要扫一遍全部历史(O(N))，KDA 每步只
更新固定大小的状态(O(1))。

### MHA：每步扫全部历史

先看被换掉的东西。给一句话逐 token 解码：「猫追老鼠，因为它饿了」。第
N 个 token 进来，和 cache 里之前 N−1 个 token 各做一次点积(图中的
连线)，softmax 成权重后加权求和 v，然后自己的 KV 追加进 cache。整句
下来点积次数累计约 N²/2：计算 O(N²)，cache O(N)。重点看 t=6 的「它」：
指代对象是 5 个 token 之前的「猫」，权重就该聚在那里：

<MhaViz client:visible />

这就是 softmax attention 的两面：检索精确，任意距离不打折；开销随
上下文一路涨，1M token 的账上一节已经算过。

### Linear attention：固定大小的状态

线性注意力去掉 softmax，乘法可以重新结合：Σ(q·kᵢ)·vᵢ 改写成
q·Σ(kᵢ·vᵢᵀ)，求和部分累加成一个固定大小的矩阵 S(每 head 约
128×128)。S 本质是一张键值表：每个 token 的 k 决定写进哪个方向，v 是
写进去的内容，读出是 `qᵀ·S`。cache 没有了，每步只碰 S。同一句话再走
一遍：

<LinearFlowViz client:visible />

「它」这一步的差别就是全部要点：上一节有一条 0.72 的线直指「猫」，这里
S 里没有位置轴，那条线画不出来，读出的是整段历史的混合。

### DeltaNet：给固定状态加删除动作

线性注意力的第一个问题不是“记不住”，而是“删不掉”。直接累加
`S = Σ k·vᵀ` 时，同一个键方向写两次，旧值和新值会一起留在 S 里。比如
这里的 A 不是 token，也不是 query，而是我们给状态空间中某个 **key 方向**
起的示意名字。模型处理第一个写入 token 时，会从这个 token 算出 key 向量
`k₁` 和 value 向量 `v₁`；图里把“`k₁` 指向 A 方向、`v₁` 表示数值 1”简写成
`A=1`。之后的 `A=4` 是另一个写入 token：它产生近似同方向的 `k₂`，但
`v₂` 表示 4。`A?` 则是第三个读取 token，它产生的 query `q` 对准 A 方向，
用 `Sᵀq` 读出这个方向当前绑定的 value。这些记号只是为了把向量运算画清楚，
并不表示模型真的看到了名为 “A=1” 或 “A?” 的文本 token。

若直接累加，`A=1` 和 `A=4` 对同一方向的贡献都会留在 S 中，下一次 `A?`
读到的是两者的混合，而不是最新值。

DeltaNet 把写入换成 delta rule：写新值之前，先用当前 k 从 S 里读出这个
方向的旧值，算出“旧值和新值差多少”，再把差值写回去。常见写法是
`S_t = S_{t−1} + β·k·(v − S_{t−1}ᵀk)ᵀ`。若旧读出是 r，那么更新后的
读出是 `r′ = r + β(v−r) = (1−β)r + βv`。因此它等价于擦掉 β 比例的旧
关联，再写入 β 比例的新关联；只有 β=1 时才是完整替换。

把一次改写拆开看：`A=4` 到来时，DeltaNet 先用 A 的 `k` 从状态里读出旧
值 1，再计算差值 `4−1=3`。图中取 β=1，所以矩阵更新既可以写成“旧读出
`1 + (4−1) = 4`”，也可以拆成“减掉旧关联 1，再加入新关联 4”；这两种
写法描述的是同一个矩阵更新：

<DeltaRuleViz client:visible />

但 DeltaNet 只解决“同键改写”。它没有回答另一个问题：固定大小的 S 被越来
越多无关历史塞满以后，哪些内容该衰减、哪些内容该保留？这就是 KDA 要继续
处理的部分。

这里还有一个必须先说清楚的现象：真实的 key 向量通常不完全正交。假设
`q_A = k_A`，状态里同时写入 `k_A·v_Aᵀ` 和 `k_B·v_Bᵀ`，那么读 A 时：
`o_A = Sᵀq_A = v_A + (k_Aᵀk_B)·v_B`。第二项就是 B 漏进 A 的串扰；它的
大小由两个 key 的内积决定。下面把问题压成二维、取 `v_A=v_B=1`：固定 A，
拖动 B 改变夹角，观察 B 在 A 上的投影如何进入 S 的读出。

<KeyOverlapViz client:visible />

### KDA：delta rule 加逐通道门控

KDA 可以理解成两层改动叠在一起：底层仍然是 DeltaNet 的“先擦后写”，解决
同键重绑定；上层再加一个由当前 token 算出的逐通道门 `Diag(α_t)`。完整顺序
是先衰减进入本步的旧状态，再做 delta update：
`S_t = (I−β_t k_t k_tᵀ) Diag(α_t) S_{t−1} + β_t k_t v_tᵀ`。

这里的 α 不是给“A、B 这些变量”各发一个开关，而是 S 的 key-channel 维度上
的保留系数向量。KDA 也不会把不正交的 key 自动旋转成正交；它做的是在新写入
之前，按通道缩小旧状态，让某些旧成分对后续读出的影响衰减。下面的图把
`Diag(α)` 单独放大：ch₁/ch₂ 是两个示意 channel，C=5 是本步新写入。为只观察
α，C 的 β 固定为 1；拖动 α₁/α₂，旧通道和最终读出会一起变化。

<KdaGateViz client:visible />

任务还可能用到的通道可以慢慢衰减，明显过期或话题外的通道可以更快让出
容量。Kimi Linear 论文把这个门控解释为一种可学习的位置编码，取代 RoPE 的
固定旋转；配套的 chunkwise kernel 在受约束的 DPLR 形式下比通用实现快约
一倍，KDA 才能铺满 69 层。

### Attention Residual

transformer 每层的输出都通过同一条残差流向后传，93 层共用这一个向量。
深层要用浅层的某个表征，前提是它经过沿途几十次相加之后仍然可分辨，层数
越深越难保证。

AttnRes 增加一条跨层通道：每 12 层一组，组末用学到的 pseudo-query 对
embedding 和之前各组的输出算注意力权重 α，按权重取回。取回哪些组、取
多少，由权重决定，不再依赖单一残差流：

<AttnResViz client:visible />

### LatentMoE

FFN 全部是 MoE：896 个 routed expert 每 token 选 16 个，另有 2 个每个
token 都经过的 shared expert。激活率 16/896 ≈ 1.8%，整模型每 token 激活
104B/2.8T ≈ 3.7% 的参数；对比 K2 的 384 选 8，稀疏度进一步提高。

路由和分发不在 7168 维 hidden 上做：先降到 3584 维隐空间，router 在半宽
向量上打分，expert 也在半宽上计算，最后升回 7168 维。16 份 dispatch 的
all-to-all 流量和 expert 权重体积都省一半：

<MoeViz client:visible />

1.8% 的激活率下训练容易不稳定，报告用了三个手段：RMSNorm、有界的
SiTU-GLU 激活，以及 Quantile Balancing(expert 配额直接从 router 分数的
分位数导出，不需要再调 aux-loss 系数)。

### 训练侧

- 量化感知训练从 SFT 阶段开始，MXFP4 权重 + MXFP8 激活，发布的权重就是
  低精度格式；
- 优化器是 Per-Head Muon，按 attention head 独立做正交化更新；
- 1M 上下文按课程拉长：8K → 64K → 256K → 1M；
- RL 覆盖 general、agentic、coding 三个域和多档 reasoning effort；工具、
  prompt、memory、subagent 等 scaffold 在训练中持续变化，避免模型只适应
  单一工作流。

## SGLang 的 Day-0 适配

上面的架构落到推理引擎里，首先要处理的是两种性质不同的推理状态：

| | MLA(24 层) | KDA(69 层) |
| --- | --- | --- |
| 状态形式 | KV cache，逐 token 追加 | 递归状态，固定大小 |
| 增长方式 | 每 token 约 27 KB，只增不减 | 每请求约 54 MB(TP=8)，每步原地覆写 |

KV 逐 token 追加、按页共享这些默认假设对 KDA 都不成立，SGLang 的适配从
这里开始。

### 双状态显存管理

旧方案在启动时把显存池按预估切成 KDA 区和 MLA 区。问题是 KDA 需求只跟并发数
相关，MLA 需求跟总上下文长度相关，负载一偏就会一侧耗尽、另一侧闲置。SGLang
改成统一池：KDA 固定块从左端分配，MLA 页从右端分配，中间是一段连续的空闲区，
按需取用：

<PoolViz client:visible />

注意 t=14：静态双池的 MLA 区耗尽，R2 生成到一半被驱逐，而 KDA 区还空着 6 页。
统一池在同一时刻没有任何失败。

前缀缓存(radix tree)这边，KDA 状态会被原地覆写，不能像 KV 那样直接共享。
SGLang 用三个操作管理它：copy-on-write(使用共享 checkpoint 前先拷到私有槽)、
snapshot(乒乓缓冲抓快照)、donate(按槽位索引捐给 radix tree)。整套设计
按构造无竞态，细节见文末博客。

### Chunked pipeline prefill

TP8 让 8 张卡合算同一个 chunk，但每层都要 AllReduce，通信在关键路径上。
chunked PP8 把模型按层切成 8 段，prompt 切成 chunk 依次流过各段，P2P 交接
藏在下一个 chunk 的计算后面(实测 91% 被隐藏)：

<PipelineViz client:visible />

预热气泡只付一次，稳态每 2 列出一个 chunk。实测 PP8 prefill 吞吐是 TEP8
节点的 1.45–1.72×(TEP = tensor + expert 并行，图中简化为纯 TP 作对照)。

### Decode context parallelism(DCP)

decode 阶段的瓶颈是显存：TP 下每张卡都存一份完整 KV。DCP 按 token 位置取模
分片，rank r 只存 `position mod N = r` 的 KV；每步 decode 先本地算局部
attention，再用一次 all-to-all 交换部分结果，log-sum-exp 合并后与单卡输出
一致：

<DcpViz client:visible />

K3 上的实测：DCP8 把逻辑上下文容量放大 7.9×；长 agent 会话下 TP8 在 16 个
并发 session 崩掉，DCP8 撑到 48 个，总吞吐 541 tok/s。KDA 状态没有位置轴，
KDA 层仍按 TP 切分，所以混合架构的并行策略也是按层混合的。

### 单卡数字

投机解码介入之前，BS=1 解码靠四类手段从 63.8 tok/s 提到约 113 tok/s
(括号内为博客给出的单项增益)：

| 类别 | 代表手段 |
| --- | --- |
| 启动开销消除(+19.9 tok/s) | MoE 前段合成单个 GEMM、KDA 投影合并、寄存器内路由 |
| 专用 kernel(+10.3) | 融合 KDA decode、W4A8 MoE、TMA 聚合 attention residual |
| 通信融合(+27.6) | 融合 all-reduce：multicast + NVLS 在交换机内归约，顺路做 residual/RMSNorm |
| 重叠与前奏(+10.4) | GEMV-GEMM 重叠、residual 写回融合、PDL 预热 attention |

在此之上，DSpark 投机解码把 BS=1 提到约 423 tok/s(约 3.7×)。

组合的 serving 边界：PP8 prefill + TP8 decode 达到 2,808 tok/s/GPU(fp4)；
交互式配置可以换到 116+ tok/s/用户。博客里值得记住的一句：

> AllReduce 是同步点，在那里省 1 微秒，步时就省 1 微秒；
> 藏在别的 stream overlap 里的 kernel，只值大约十分之一。
