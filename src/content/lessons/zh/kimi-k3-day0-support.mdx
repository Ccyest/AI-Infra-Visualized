## Kimi K3 的架构

K3 是一个 2.8T 参数的 MoE 模型，每个 token 激活 104B 参数。它原生支持 1M 上下文。K3
一共有 93 层，其中 69 层是 KDA 线性注意力，24 层是带门控的全局 MLA；第一层使用 dense
FFN，其余 92 层使用 Stable LatentMoE。并且，每 12 层组成一个 block，Attention
Residual 会跨 block 聚合。点击下图可以先看完整结构：

<ArchViz client:visible />

### KV cache memory estimation

先从显存看：无论 MLA 还是 MHA，KV cache 都会随上下文增长。在 Kimi K3 Day-0 Support
博客中，我们看到，MLA 压缩后，K3 每层每个 token、每张 GPU 约需 1.1KB KV cache，24 层
MLA 合计约 27KB。如果 93 层全部使用 MLA，单张 GPU 上的 1M-token 请求要占约
110GB（1.1KB × 93 层 × 1M token）；未压缩的 MHA 还要再大一个数量级。
把这部分显存降下来是必须先解决的问题，所以显然，K3 不能在大部分层保留随上下文增长的
softmax attention。

因此，K3 采用 3 KDA + 1 MLA 的交错结构。KDA 作为 linear attention 的变体，
递归状态大小固定，不会随上下文增长（具体方法后文会阐述）。每张 GPU 每请求约 54MB，
每步原地更新；MLA 保留全局 attention。全模型不使用显式位置编码（NoPE），位置信息由
KDA 的递归隐式提供。下图展示了全部使用 MLA 和 KDA+MLA 混合方案的显存使用量区别：

<CacheViz client:visible />

接下来，我们会详细讲解一下从最初的传统 MHA 到 KDA，attention 机制有什么异同，
帮助大家理解为什么 Kimi K3 会选择 linear attention 的变体 KDA。

### attention 机制详解：传统 MHA

在普通 MHA 中，解码到第 $t$ 个 token 时，它会读取 cache 里前面 $t-1$ 个历史 token，分三步计算：

1. **打分**：对每个历史 token $i$ 计算分数 $z_{t,i} = \frac{q_t \cdot k_i}{\sqrt{d_k}}$。下标 $t,i$ 读作「第 $t$ 步的 query 对第 $i$ 个历史 key」。
2. **归一化**：先求 $Z = \sum_{j=1}^{t-1} \exp(z_{t,j})$，再得到注意力权重 $a_{t,i} = \exp(z_{t,i}) / Z$。
3. **汇总**：用这些权重对 value 加权求和，$o_t = \sum_{i=1}^{t-1} a_{t,i} \cdot v_i$。

长度为 $N$ 的序列累计约有 $N^2/2$ 次点积，计算为 $O(N^2)$，cache 为 $O(N)$。
如图所示，每一个 token 都和之前的所有 history token 有连线。

<MhaViz client:visible />

softmax attention 换来了逐位置读取能力，因此有最完整的全局记忆，但是代价也很明显。
因为每个新 token 都要重新扫描全部历史，所以我们需要存储全部历史，并且计算量是
$O(N^2)$。

### attention 机制详解：linear attention

线性注意力不再保存每个 token 的 KV，而是把历史写入累加到固定大小的矩阵
$S = \sum_i k_i v_i^{\top}$ 里。S 作为固定大小的记忆矩阵，每一步新 token
算完都会重新写入 S：k 决定写入方向，也就是这个 token 在向量空间里指向哪儿，v
是沿这个方向写入的内容，q 再用 $o = S^{\top} q$ 读取。无论上下文多长，
每步都只读写这个 S。

<details className="lesson-details">
  <summary>数学细节：128×128 状态中的 head 和 channel</summary>
  <p>K3 的 hidden size 为 $d_{\text{model}} = 7168$。对第 $h$ 个 KDA head（共 96 个），三个学习投影 $W_q^h, W_k^h, W_v^h \in \mathbb{R}^{128 \times 7168}$ 把 $x_t \in \mathbb{R}^{7168}$ 映射为 $q_t^h = W_q^h x_t$、$k_t^h = W_k^h x_t$、$v_t^h = W_v^h x_t \in \mathbb{R}^{128}$。head 是学习出的 128 维特征空间，不是把 7168 个输入坐标原样切开；下文固定一个 head 并省略上标 $h$。</p>
  <p>Naive linear attention 的状态是 $S_t \in \mathbb{R}^{128 \times 128}$（约定：行 = key 通道，列 = value 通道），更新与读出为 $S_t = S_{t-1} + k_t v_t^{\top}$、$o_t = S_t^{\top} q_t$。外积 $k_t v_t^{\top}$ 的第 $j$ 行是 $k_t[j]\, v_t^{\top}$：key 的第 $j$ 个坐标（第 $j$ 条 key channel）决定 $v_t$ 以多大的系数写进 S 的第 $j$ 行，因此 $S_t[j,:] = \sum_{s \le t} k_s[j]\, v_s^{\top}$。</p>
  <p>把读出展开：$o_t = \sum_{s \le t} (k_s^{\top} q_t)\, v_s$。它和 softmax attention 的差别只在权重：这里是未归一化的内积 $k_s^{\top} q_t$，而不是 softmax 之后的 $a_{t,s}$——没有位置轴，也没有归一化。</p>
  <p>规模：每个 head 有 $d_k \times d_v = 128 \times 128 = 16{,}384$ 个状态标量，96 个 head、69 层合计固定不变；每步更新和读出的计算量都是 $O(d_k d_v)$，与上下文长度无关。把 $d_k$ 或 $d_v$ 加倍，状态与每步计算都按 $d_k \times d_v$ 增长——这就是取 128 的容量/开销折中。</p>
</details>

### attention 机制详解：DeltaNet

Naive linear attention 的问题是，状态只会不断累加，不会覆盖旧值。最简单的例子来说，
同一个 key 方向先写入 1、再写入 4，两个值都会留在 S 里；在这个简化例子中，
下次读取会得到 $1+4$。虽然上下文不同，通常会使同一个词产生不同的 key，但在 1M token
这样的长序列下，有限容量的状态仍可能难以清晰地区分这些信息。比如，
前面先读到「张三住在北京」，于是状态里写入「张三 → 北京」；
后面又读到「张三搬到了上海」。那此时问到张三住在哪里，
读出来的结果很可能就是北京和上海这两条信息的混合，而不是明确地用「上海」覆盖「北京」
。

DeltaNet 的解决方案是对状态做基于误差的定向修改。它引入动态生成的标量门控
$\beta_t$，控制当前更新的强度。写入前，模型先沿当前 key 读出状态已有的预测
$r_{\text{old}} = S_{t-1}^{\top} k_t$，随后不再累加 $v_t$，
而是写入目标值与已有预测之间的差：
$S_t = S_{t-1} + \beta_t k_t (v_t - r_{\text{old}})^{\top}$。对已归一化的 key，
更新后的读出为 $r_{\text{new}} = (1-\beta_t)\, r_{\text{old}} + \beta_t v_t$。

$\beta_t$ 控制改写强度：$\beta_t = 1$ 代表完全替换旧关联，$\beta_t$ 越小，
旧值保留得越多；$\beta_t = 0$ 则完全不改写。

<DeltaRuleViz client:visible />

这解决了同方向改写，却还有一个容量问题：无关历史不断进入固定大小的 S 后，
什么应该衰减？即使是无关的 key 向量，在真实情况下大部分也并不完全正交，
一个方向的写入会投影到另一个方向，产生串扰。在超长上下文中，影响只会越来越大。

<details className="lesson-details">
  <summary>数学细节：图中的 A/B 和串扰项</summary>
  <p>A、B 是 key 空间 $\mathbb{R}^{d_k}$ 中的两个单位方向 $k_a, k_b$（$\lVert k_a \rVert = \lVert k_b \rVert = 1$），不是 token 槽位，也不是单条 channel。图中的 $A=1$ 只是“key 指向 $k_a$、value 为标量 1”的简写；彩色只用于追踪各次写入的来源，真实 S 只保存它们的和。</p>
  <p>设 S 中已写入两条关联：$S = k_a v_a^{\top} + k_b v_b^{\top}$。用 $q_a = k_a$ 读出，得 $o_a = S^{\top} q_a = (k_a^{\top} k_a)\, v_a + (k_b^{\top} k_a)\, v_b = v_a + \cos\theta \cdot v_b$，其中 $\theta$ 是两个 key 的夹角。第二项就是 B 漏进 A 的串扰，系数恰好是内积 $k_a^{\top} k_b$。</p>
  <p>推广到任意一组写入 $\{(k_i, v_i)\}$：读出为 $o(q) = \sum_i (k_i^{\top} q)\, v_i$，各条写入之间的干扰由 Gram 矩阵 $G_{ij} = k_i^{\top} k_j$ 决定。当且仅当所有 key 两两正交时读出零串扰；而 $\mathbb{R}^{d_k}$ 中至多只有 $d_k$ 个两两正交的方向，存的关联一旦超过这个数，固定大小状态里的串扰就无法消除，只能被管理。</p>
</details>

### attention 机制详解：KDA

固定状态的大小不会随上下文增长，这正是它省显存的原因；
代价是越来越多的历史必须共享同一个 S。Delta rule 能改写相同或相近的 key 方向，
却不会主动清理所有旧的无关信息，也就是上面的串扰。KDA 因此再加入逐 channel 门控：
对每个 token、每个 head，模型根据当前 hidden state 动态算出向量 $\alpha_t$，先用
$\mathrm{Diag}(\alpha_t)$ 缩放旧状态的各条 channel，再执行 DeltaNet 改写。

<details className="lesson-details">
  <summary>数学细节：KDA 如何门控和改写同一个 S</summary>
  <p>完整更新为 $S_t = \big(I - \beta_t k_t k_t^{\top}\big)\,\mathrm{Diag}(\alpha_t)\, S_{t-1} + \beta_t k_t v_t^{\top}$。逐项看：$\alpha_t \in (0,1)^{d_k}$ 是由当前 hidden state 算出的向量门控，$\mathrm{Diag}(\alpha_t)$ 把 S 的第 $j$ 行整体缩放 $\alpha_t[j]$ 倍——同一行里所有历史贡献一起衰减，它不会直接选择 A 或 B，也不会把 key 旋转成正交；$\beta_t \in (0,1)$ 是标量写入强度。</p>
  <p>把一步更新拆开看。先门控：$\tilde S = \mathrm{Diag}(\alpha_t)\, S_{t-1}$；再沿当前 key 做 delta 改写：记 $r_{\text{old}} = \tilde S^{\top} k_t$（衰减后状态对当前 key 的预测），则 $S_t = \tilde S + \beta_t k_t (v_t - r_{\text{old}})^{\top}$。对单位 $k_t$，更新后沿同一 key 的读出为 $S_t^{\top} k_t = (1-\beta_t)\, r_{\text{old}} + \beta_t v_t$：$\beta_t = 1$ 完全替换，$\beta_t = 0$ 完全保留。</p>
  <p>把递推展开可以看到位置信息的来源：$S_t = \sum_{s \le t} \Big[\prod_{u=s+1}^{t} \big(I - \beta_u k_u k_u^{\top}\big)\mathrm{Diag}(\alpha_u)\Big]\, \beta_s k_s v_s^{\top}$。越早的写入要穿过越多次门控与改写，衰减随距离自然累积——这正是 K3 可以不用 RoPE 的机制来源。K3 还给 $\alpha$ 设衰减下界、配 full-rank output gate，保证长序列下数值稳定。</p>
  <p>下图把真实的 128 维 key 空间压成二维教学切片：$k_a = \tfrac{1}{\sqrt{2}}[1,1]^{\top}$、$k_b = \tfrac{1}{\sqrt{2}}[1,-1]^{\top}$，A/B 都横跨 $\mathrm{ch}_1$ 和 $\mathrm{ch}_2$。门控先缩放两行，delta rule 再沿完整 $k_a$ 写入到达目标值 4 所需的残差。</p>
</details>

<KdaGateViz client:visible />

由此可见，Kimi K3 不需要 RoPE，是因为 KDA 的状态更新本身就带有位置信息。越早出现的
token，在传递到当前位置前会经历更多次衰减和状态变换；越近的 token 经历的变换更少，
因此模型可以据此感知顺序和距离。相比 RoPE 用固定旋转显式编码位置，KDA 通过可学习、
输入相关的衰减隐式建模位置。K3 还加入衰减下界约束和 full-rank output gate，
以提升稳定性。

### Attention Residual

传统 Transformer 的 residual stream 像一份从底层一路传到顶层的草稿：
每一层都会在上面继续修改。它保证信息能够向上传递，但到了第 90 多层，
浅层细节已经和几十次更新叠在一起，深层无法单独翻回某个较早版本。

Attention Residual 相当于额外保存几份「历史版本」。K3 把所有 layer 按 block 切开，
每个 block 包含 12 层。block 内保留普通 residual，同时把每个 12-layer block
的层输出累加成一份 block 表示。后续层不必只依赖当前草稿，而是用学到的 pseudo-query
给 embedding 和这些历史摘要分配权重，把此刻最有用的几份表示混合取回：

<details className="lesson-details">
  <summary>数学与成本：为什么 K3 每 12 层保存一份摘要</summary>
  <p>记 $v_0$ 为 embedding，$v_i$（$i \ge 1$）为第 $i$ 个 block 的摘要（该 block 内 12 层输出的累加）。对后续 block $\ell$，学习到的 pseudo-query $q_\ell$ 给每份已保存的表示打分，$\alpha_{\ell,i} = \mathrm{softmax}_{i \lt \ell}\big(s(q_\ell, v_i)\big)$（$s$ 为点积型打分），再取回 $r_\ell = \sum_{i \lt \ell} \alpha_{\ell,i}\, v_i$，加入该 block 的输入。这是对历史表示的 softmax 加权混合：权重可以集中到某一份摘要上，但永远不是硬选择。</p>
  <p>成本：full AttnRes 每 token 要存全部 $L$ 层输出，即 $O(Ld)$；block 版只存 $N = \lceil L/12 \rceil$ 份摘要加 embedding，即 $O(Nd)$。K3 取 $L = 93$、块大小 12，即 $N = 8$ 份摘要，每 token 保存 $9 \times 7168$ 个数。这些摘要还要随 activation 一起走 pipeline，所以 $N$ 直接进入通信量。</p>
  <p>粒度与成本的折中：块越小（极端是一层一块），跨深度取回越精细，但状态、显存带宽和 pipeline 通信按 $N$ 线性变贵；块越大越便宜，但块内各层输出已经相加，无法再单独取回。优化实现下，K3 的典型推理延迟开销低于 2%，pipeline parallelism 下训练墙钟开销低于 4%。</p>
</details>

### LatentMoE

除第一层 dense FFN 外，K3 的其余 FFN 使用 MoE：896 个 routed experts 中每个 token 选
16 个，另有 2 个 shared experts 始终激活。因此 routed pool 的选中比例是
$16/896 \approx 1.8\%$；整模型每 token 激活参数的另一个口径是
$104\text{B}/2.8\text{T} \approx 3.7\%$。

路由和 expert 计算会先从 7168 维 hidden 降到 3584 维隐空间，最后再升回原宽度。
这使 16 份 dispatch 的 all-to-all 流量和 expert 权重体积都减半：

## SGLang 的 Day-0 适配

K3 的混合架构会产生两种生命周期完全不同的推理状态：

| | MLA（24 层） | KDA（69 层） |
| --- | --- | --- |
| 状态形式 | KV cache，逐 token 追加 | 递归状态，固定大小 |
| 增长方式 | 每 token、每 GPU 约 27KB，只增不减 | 每请求、每 GPU 约 54MB（`TP=8`），每步原地覆写 |

MLA 的 KV 随 token 追加，KDA 的状态却按请求固定占用并且每步覆写。下面的适配重点，
就是如何同时管理这两种状态，并据此选择 prefill 和 decode 的并行方式。

### RadixAttention：如何给 KDA 做前缀缓存

传统 RadixAttention 能让多个请求共享前缀，是因为传统的 attention KV 只随 token
增多而追加，不改写原有历史。但 KDA 的递归状态 $S$ 每读入一个 token 都会原地覆写。
假设 D 和 E 都命中前缀 ABC，如果它们直接共用同一份 $S(\text{ABC})$，D
先跑一步就会把它变成 $S(\text{ABCD})$，E 也就无法再从 ABC 的状态开始，
因此从机制上破坏了 prefix cache 的可能性。那么我们该如何维持 RadixAttention
的缓存树呢？

所以，SGLang 的方法是：不让请求直接改 radix tree 上的共享状态。它把树上的 KDA
状态当作只读 checkpoint：命中前缀后，先 copy-on-write 到请求的私有工作槽，再让
forward 原地改写这份副本，通过复制与分叉，避免了覆写造成的 prefix 被破坏。下图中，
图一对比了 KDA 和 MLA 在两种负载下的 radix cache 增长方式，图二逐步演示
copy-on-write、snapshot、donate 和 checkpoint 淘汰等机制：

### 双状态显存管理

因为 K3 使用了 KDA 和 MLA 的混合层架构，所以在显存管理上，我们也需要切出不同的分区。
原方案在启动时预先切出 KDA 区和 MLA 区。但 KDA 需求取决于并发数，MLA
需求取决于总上下文长度，一旦负载偏离预估，就会出现一边耗尽、另一边空着的情况。
其实解决方法非常直接，SGLang 把两者放进同一个池：KDA 固定块从左边分配，MLA
页从右边分配，共用中间的空闲区，这样可以让显存尽量打满。Day-0 版本通过
`--enable-unified-memory` opt-in：

### Chunked pipeline prefill

Prefill 一次处理大量 prompt tokens，有足够工作可以切成 chunks 灌满流水线。TP8 让 8
张卡同时进行 prefill 工作，但是问题在于：每经过一层，都需要锁步进行 AllReduce，
以获得完整结果进入下一层。而 chunked PP8 则不同，PP8 把 93 层按深度分给 G1–G8，
让不同 GPU 同时处理不同 chunk。GPU 之间只传递上一段层的 activation，这些 P2P
传输可以与下一 chunk 的计算重叠。如图所示，G1–G8 各自跑的都是一段完整的层，
而不是把单层切成 8 份，所以不需要每一层之间都进行 AllReduce。
当然代价是灌入和排空需要一定过程，没办法上来就打满，不过在长上下文的 prefill 中，
这些开销会被稀释，所以整体效率会提升。

<PipelineViz client:visible />

当然，decode 是另一个故事。Decode 每步通常只有一个新 token，不足以灌满 PP8
这样的深流水线，所以 TP8 仍然更合适。PD disaggregation 下的典型分工是
`PP8 prefill → TP8 / DCP8 decode`。前文也讲过，PP 也会产生灌入和排空开销，当请求或
chunk 太少时并不占优。

### Decode context parallelism（DCP）

MLA 虽然有多个 attention heads，但所有 heads 共享同一份压缩 KV latent，所以当 TP 按
head 分片的时候，不像 MHA，压缩后的 KV latent 没有一个清晰的轴去分片。因此，TP8
的每张卡都必须复制完整 MLA KV latent。这意味着，每一张 GPU 上都有重复的 MLA KV
latent，因此，就算增加 GPU 并行，也不会增加逻辑上下文容量。而 SGLang 使用 DCP，
改为按 token 位置分片：每张卡先在本地 $1/N$ KV 上计算 partial attention，
如图所示进行分开分配，再通过一次 packed all-to-all 精确合并：

<DcpViz client:visible />

DCP 主要增加容量和并发，不是降低单条短请求的延迟。它让更多长会话留在 GPU，避免 host
offload 和 re-prefill 造成吞吐坍塌。K3 上，DCP8 把逻辑容量从 1.5M 提到 12.2M
tokens（7.9×），48 个 agent sessions 达到 541 tok/s。代价是每个 MLA 层多一次
all-to-all；当然，KDA 状态 S 不会随上下文增长，也没有 token 的位置轴，所以仍按
TP/head 切分。
