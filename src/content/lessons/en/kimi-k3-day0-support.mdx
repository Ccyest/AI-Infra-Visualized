> **TL;DR** K3 swaps 69 of its 93 layers to KDA linear attention so KV cache
> grows in only 24 layers, adds AttnRes across depth, and makes every FFN a
> 16-of-896 LatentMoE. Landing that architecture breaks many default
> assumptions in a serving stack: SGLang's day-0 support comes down to a
> unified memory pool, chunked-PP prefill, and DCP decode, plus speculative
> decoding with DSpark.

## Do the math first: KV cache at 1M tokens

The basics: 2.8T parameters, 104B active, 93 layers, native 1M context, MXFP4
weights, native vision (MoonViT3d). That "1M context" immediately rules out
softmax attention in all 93 layers: extrapolating from the compressed-MLA rate
of 27 KB/token (across 24 layers), an all-MLA stack of 93 layers would need
about 110 GB per request at 1M tokens, and uncompressed MHA is an order of
magnitude beyond that.

K3's answer: 93 layers = 69 KDA + 24 MLA, interleaved 3 KDA + 1 MLA. KDA
layers are linear attention with a fixed-size state (≈0.4 GB per request in
total), overwritten in place every step; MLA layers keep global attention and
drop RoPE entirely (NoPE), since KDA's recurrence carries position on its own:

<CacheViz client:visible lang="en" />

The 24 MLA layers hold about 28 GB at 1M tokens, 1/3.9 of the all-MLA
hypothetical. Compute tells the same story: softmax attention scans the whole
history for every generated token (O(N)); KDA touches a fixed state (O(1)).

## KDA: how a fixed-size state remembers

Linear attention removes the softmax so the multiplication re-associates: the
whole history compresses into one fixed-size matrix S (≈128×128 per head).
Writing is `S += k·vᵀ`, reading is `qᵀ·S`. That is O(1) per step, but
add-only: write the same key direction twice and the old and new values stack,
so a query reads back a blend.

DeltaNet replaces the write with the delta rule: use k to read the old value,
erase it with write strength β, then write the new one,
`S_t = (I − β·k·kᵀ)·S_{t−1} + β·k·vᵀ`. This is online gradient descent on
"S·k should equal v", and rebinding now works. But the state still only fills
up: every written key occupies the limited dimensions forever, and the longer
the context, the more crosstalk each read picks up.

Gated DeltaNet adds a forget gate, one scalar per head: everything forgets
together. KDA refines it into a per-channel diagonal gate,
`S_t = (I − β·k·kᵀ)·Diag(a_t)·S_{t−1} + β·k·vᵀ`, where a_t is computed from
the current input and every channel gets its own forgetting rate. The Kimi
Linear paper reads this as a learnable position encoding: RoPE's fixed
rotation swapped for data-dependent decay. A chunkwise kernel for the
constrained DPLR form runs about twice as fast as the general algorithm,
which is what makes covering 69 layers affordable.

## Across depth: Attention Residual

The residual stream is the transformer's trunk line: every layer reads from
it, adds to it, and passes it on. With 93 layers sharing one trunk, every
intermediate representation squeezes through the same vector; a deep layer
that needs something specific from a shallow one can only hope it survived
dozens of additions along the way.

AttnRes opens a second path: every 12 layers form a group, and a learned
pseudo-query scores the embedding plus all preceding groups' outputs with
attention weights α, retrieving them by weight into the current
representation. Retrieval is selective, taking exactly the groups it needs
instead of accumulating everything along one stream:

## FFN: LatentMoE, 16 of 896

Every FFN is MoE: 896 routed experts with 16 chosen per token, plus 2 shared
experts that are always on. The activation ratio is 16/896 ≈ 1.8%, and the
model activates 104B/2.8T ≈ 3.7% of its parameters per token (K2 was 8 of
384; K3 pushes sparsity one notch further).

Where routing happens also changed: instead of the 7168-d hidden width,
tokens first project down to a 3584-d latent space; the router scores the
half-width vector, experts compute at half width too, and the result projects
back up. The 16-way all-to-all dispatch traffic and the expert weights both
halve as a result:

<MoeViz client:visible lang="en" />

Keeping training stable at 1.8% activation takes three things: RMSNorm,
bounded SiTU-GLU activations, and Quantile Balancing, where expert quotas
derive directly from router-score quantiles, removing the sensitive aux-loss
coefficient entirely.

## A few things on the training side

- Quantization-aware training starts at the SFT stage: MXFP4 weights with
  MXFP8 activations, so the release is natively low-precision;
- The optimizer is Per-Head Muon: Muon's orthogonalized updates applied per
  attention head;
- The 1M context is grown on a curriculum: 8K → 64K → 256K → 1M;
- RL covers general, agentic, and coding domains across multiple
  reasoning-effort levels; tools, prompts, memory, and subagent scaffolds keep
  changing during training so the model doesn't overfit one workflow.

## From architecture to serving: two state types

Inside an inference stack, the first direct consequence of this architecture
is two kinds of inference state:

| | MLA (24 layers) | KDA (69 layers) |
| --- | --- | --- |
| State shape | KV cache, appends per token | Recurrent state, fixed size |
| Growth | ~27 KB per token, append-only | ~54 MB per request (TP=8), overwritten in place each step |

The default assumptions of a serving stack, per-token KV appends and
page-level sharing, hold for neither KDA property. SGLang's day-0 work starts
here.

## Memory management for two state types

The old approach carves the memory pool into a KDA region and an MLA region at
startup, based on a guess. But KDA demand tracks concurrency while MLA demand
tracks total context length, so a skewed workload exhausts one side while the
other sits idle. SGLang switched to a unified pool: fixed KDA blocks allocate
from the left, MLA pages from the right, and the middle stays contiguous free
memory:

<PoolViz client:visible lang="en" />

Watch t=14: the split layout's MLA side runs out and R2 is evicted
mid-generation, while 6 KDA pages are still free. The unified pool has no
failures at the same moment.

On the prefix-cache (radix tree) side, KDA state is overwritten in place and
cannot be shared like KV. SGLang manages it with three operations:
copy-on-write (restore a shared checkpoint to a private slot before mutating),
snapshot (ping-pong buffered capture), and donate (hand the state to the radix
tree by slot index). The design is race-free by construction; details in the
blog below.

## Chunked pipeline prefill

TP8 has all 8 GPUs co-compute each chunk, with an AllReduce every layer, so
communication sits on the critical path. Chunked PP8 splits the model into 8
stages by layer and streams prompt chunks through; P2P hand-offs hide behind
the next chunk's compute (91% hidden in practice):

<PipelineViz client:visible lang="en" />

The warm-up bubble is paid once; at steady state a chunk ships every 2 columns.
Measured: PP8 prefill delivers 1.45–1.72× the throughput of a TEP8 node
(TEP = tensor + expert parallelism; the diagram simplifies it to plain TP).

## Decode context parallelism (DCP)

Decode's bottleneck is memory: under TP every GPU stores a full copy of the KV.
DCP shards by token position, so rank r keeps only the positions where
`p mod N = r`. Each decode step runs local attention first, then one
all-to-all exchanges the partial results; a log-sum-exp merge reproduces the
single-GPU output exactly:

<DcpViz client:visible lang="en" />

Measured on K3: DCP8 multiplies logical context capacity by 7.9×. On long
agent sessions TP8 collapses at 16 concurrent sessions, while DCP8 sustains 48
at 541 tok/s. KDA state has no position axis, so KDA layers stay TP-sharded —
with a hybrid model, parallelism is also per-layer hybrid.

## Single-GPU numbers

Before speculation, BS=1 decode went from 63.8 tok/s to about 113 tok/s
through four families of work (per-item gains from the blog in parentheses):

| Family | Representative moves |
| --- | --- |
| Launch elimination (+19.9 tok/s) | Collapse the MoE front into one GEMM, merge KDA projections, register-resident routing |
| Dedicated kernels (+10.3) | Fused KDA decode, W4A8 MoE, TMA attention-residual aggregation |
| Communication fusion (+27.6) | Fused all-reduce: multicast + NVLS in-switch reduction with residual/RMSNorm folded in |
| Overlap & prologue (+10.4) | GEMV–GEMM overlap, fused residual write-back, PDL attention arming |

On top of that, DSpark speculative decoding lifts BS=1 to about 423 tok/s
(~3.7×).

The combined serving frontier: PP8 prefill feeding TP8 decode reaches
2,808 tok/s per GPU (fp4); interactive configs trade down to 116+ tok/s per
user. One line from the blog worth remembering:

> All-reduce is a synchronization point, so a microsecond saved there converts
> one-for-one into step time; a kernel in another stream's overlap slack
> converts at roughly one-tenth.
